# AEGIS — Status

Plain status for external review. This is intentionally *not* an architecture
doc — it says where the project is and what its numbers do/don't mean, without
the system-design detail. Detailed design docs (`design.md`, `eval_design.md`,
`test_suite.md`, `ui.md`) are maintained privately and available on request.

## Build phase

- **Phase 0 — foundation** (telemetry plane, failure classifier, epoch
  service, escalation policy engine, chaos-injection harness): done.
- **Phase 1 — real per-layer math** (NIC migration state machine + bandwidth
  math; real torch MeCeFO tensor math — low-rank SVD, skip-connection,
  selective recompute; real file-based differential checkpoints with SHA-256
  verification; cross-layer recovery consensus wired into routing): done at
  the software-composition level. Hardware validation is the open item — see
  below.
- **Phase 2 — economics** ($/GPU-hr KPI meter wired into the runtime,
  text/JSON operator dashboard, benchmark suite generating the comparison
  report below): done at the software/simulation level.
- **Phase 3 — moat extensions** (learned classifier, predictive pre-staging,
  straggler tier, inference-path coverage): not started, deferred by design.

## Hardware validation — in progress

**Currently running an expanded benchmark suite on an NVIDIA A100 research
cluster; results imminent.** This is the validation gate for the numbers
below — real fault injection, real recovery, real stopwatch timing, not the
target-cost-table model the current report uses.

## What the report below is and isn't

The following is a real benchmark report generated by the project's own
tooling (`bench/run_st3.py`, FT-PRODUCTION trace, seed=2024) — not hand-picked
numbers. Read it with its own caveat in mind:

- AEGIS's recovery-time input comes from a real routing decision (the actual
  escalation policy engine, driving the actual runtime) combined with a
  *target* per-tier recovery-time model — not a hardware-measured duration.
- The five baseline systems (B-VANILLA, B-R2CCL, B-MECEFO, B-TIERCHECK,
  B-TORCHFT) are simulated cost-table baselines in this report, not real
  integrations run side by side.
- This is useful for confirming the routing logic and composed-tier economics
  are directionally correct. It is **not yet a validated $/GPU-hr claim** —
  that's what the A100 cluster run in progress now is for.

## Live/dashboard numbers

`aegis.dashboard()` reports real measured recovery time from the actual
runtime as it runs. On a non-GPU dev machine, that's CPU/MPS proxy timing
(sub-millisecond), not representative of production recovery cost. This is a
different, smaller number than the ST-3 report above and shouldn't be
conflated with it.
